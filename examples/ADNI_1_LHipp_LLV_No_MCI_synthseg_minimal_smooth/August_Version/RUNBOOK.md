## Equations and losses

Plain ODE and BrainODE integrate

`dz/dt = f_theta(z(t), t, d)`

with fixed-step RK4. Their only optimizer objective is

`L_ODE = mean ||z_hat_i(t_j) - z_i(t_j)||_2^2`

over all forward suffix and backward prefix trajectories. Augmentation adds one
shared latent perturbation/scale per trajectory, as in the earlier BrainODE
implementation. The frozen decoder is used only for validation selection and
evaluation; it is absent from `L_ODE`.

BrainODE uses the released Q/K/V form under singleton-case semantics. Each
subject trajectory is evaluated independently, so derivatives cannot depend on
unrelated subjects in the optimization batch.

Direct C4 is not an ODE:

`Phi(z,s,t,d) = z + (t-s) [v_CN(z,s,t) + d v_AD(z,s,t)]`.

It uses the original C4 weights after renaming PCA-specific terms to generic
latent terms:

- real forward/backward latent and decoded-vertex reconstruction;
- observed and virtual semigroup consistency;
- inverse consistency;
- direct and rollout sequence latent/decoded-vertex losses;
- sequence semigroup consistency;
- decoded volume, log-volume rate, sequence slope, diagnosis-group rate, and AD-CN rate-gap losses.

The decoder is frozen (`requires_grad=False`, evaluation mode) but remains in
the differentiable graph for C4. Thus reconstruction gradients pass through the
decoder to the predicted latent and flow, while decoder weights never update.
Coboundary is prohibited by config validation and fixed to exactly zero.

## Prepared representations

The current task archives have already been prepared and verified. The command
below is the reproducibility command for a new task/output version; it will
intentionally refuse to overwrite the current archives.

From the repository root:

```bash
examples/ADNI_1_LHipp_LLV_No_MCI_synthseg_minimal_smooth/August_Version/scripts/prepare_gpu.sh 1
```

checks exact scan order and subject split isolation, freezes the decoders, and
records reconstruction floors. It refuses to overwrite an existing prepared
representation.

## Standalone full-training command

To start the selected PCA128 and SpiralNet++128 direct-C4 experiments as two
independent background processes sharing physical GPU 1:

```bash
examples/ADNI_1_LHipp_LLV_No_MCI_synthseg_minimal_smooth/August_Version/scripts/launch_pca_spiral_c4_parallel_gpu.sh 1 42
```

Each run has its own PID, log, status JSON, checkpoint directory, validation,
and test report. A third lightweight watcher waits for both runs and then writes
the selected two-model comparison tables. Sharing one GPU may increase each
run's wall time; the jobs remain scientifically and filesystem-independent.
The launcher uses detached `screen` sessions so the work survives the launching
terminal or API process. Monitor the active seed-42 jobs with:

```bash
tail -f /mnt/bulk10tb/Deep3DComp/ADNI_1_LHipp/August_Version/jobs/pca128_direct_c4_s42_screen1/job.log
tail -f /mnt/bulk10tb/Deep3DComp/ADNI_1_LHipp/August_Version/jobs/spiralnet128_direct_c4_s42_screen1/job.log
screen -ls
```

Example: SpiralNet++ direct C4 on physical GPU 1:

```bash
examples/ADNI_1_LHipp_LLV_No_MCI_synthseg_minimal_smooth/August_Version/scripts/run_one_gpu.sh \
  examples/ADNI_1_LHipp_LLV_No_MCI_synthseg_minimal_smooth/August_Version/configs/spiralnet128_direct_c4_s42.json \
  1 42 spiralnet128_direct_c4_s42
```

The launcher sets `CUDA_VISIBLE_DEVICES`, so the Python process intentionally
uses `cuda:0` inside that isolated view. Change the physical GPU argument as
needed.

To run all nine models for seeds 42, 43, and 44 sequentially on physical GPU 1:

```bash
examples/ADNI_1_LHipp_LLV_No_MCI_synthseg_minimal_smooth/August_Version/scripts/run_full_matrix_gpu.sh 1 "42 43 44"
```

This is a long launcher and is not part of automated smoke verification.

## Validation and test

Training loads only train and validation archives. After a run is selected:

```bash
/home/jakaria/anaconda3/envs/pytorch_geo/bin/python \
  examples/ADNI_1_LHipp_LLV_No_MCI_synthseg_minimal_smooth/August_Version/scripts/evaluate.py \
  --run-dir /mnt/bulk10tb/Deep3DComp/ADNI_1_LHipp/August_Version/training/spiralnet128/direct_c4/spiralnet128_direct_c4_s42 \
  --split test --device cuda:1
```

The evaluator reports representation floor, no-change, transport-only decoded
error, end-to-end raw-mesh error, volume/rate, CN/AD, adjacent/non-adjacent,
first-to-last, matched forward/backward horizon bins, one-shot/rollout,
semigroup and inverse defects, and subject-bootstrap confidence intervals.
It refuses to overwrite a report. Pass `--evaluation-name evaluation_v2` to
write a second, separately named evaluation, and pass the same option to
`compare_results.py`.

Use `compare_results.py` with the nine chosen run directories to require and
assemble a complete 3x3 validation or test matrix. Besides the compact summary
CSV, it writes companion `_pairs.csv`, `_sequences.csv`, and `_bootstrap.csv`
tables. The pair table contains every available CN/AD/overall, adjacent,
non-adjacent, first-last, forward/backward, and horizon stratum with no-change,
transport-only, end-to-end, volume, and rate fields. The sequence table contains
matched forward/backward direct (one-shot) and rollout fields.
